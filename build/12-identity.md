## What to build

1. **Candidates as modules** (`identity.cand.court`, `identity.cand.dime`, `identity.cand.fec`, `identity.cand.ftm`, `identity.cand.harvard_local`, `identity.cand.legislators`, `identity.cand.voter_file` under `[stages.identity]`, policy `all`; a source whose `ref_*` table is not loaded, or whose flag is off, is skipped with the reason). For each row, gather person records from: the court record (`identifiers`: middle name, dob or age, city, case number, office, employer, aliases, each with its capture); `ref_candidates_all` (DIME, FEC, FTM, Harvard local, congress, state legislators) by surname and state with alias expansion (an `aka` in the Name column is expanded into the candidate set; the spec says excluding them costs recall at no false-positive benefit); and, only if `first_pass.voter_file_enrichment` is true, a voter-file source (not in this pass). Write `identity_candidates` with `source`, `fields_json`, and later the prior, weight, posterior and waterfall.
2. **Population prior, stored per candidate:** prior odds = 1 / N_namesakes, with N_namesakes ≈ p(surname) × p(given name | sex, birth cohort) × N_adults(state, cohort). `p_surname` from `ref_surname_freq`, with the documented floor for absent surnames (report how many rows hit the floor). `p_given` from SSA national counts conditioned on sex (inferred from the given name's SSA sex ratio; ambiguous names use both and the report says how many) and a birth cohort from the court record's dob or age, widened to ±5 years when only an age at sentencing is known; the by-state SSA file where the state has enough volume. `N_adults` from `ref_population`. Store all three components in `fields_json` so the prior is reproducible. A row with no age or dob gets a cohort-free prior over all adults, which is deliberately weak.
3. **Evidence model.** Splink 4.0.x on the DuckDB backend with exactly the comparison columns and levels in spec section 8: surname (exact; Jaro-Winkler ≥ 0.92; Double Metaphone equal; else) with term-frequency adjustment on, `tf_minimum_u_value = 1e-4`, weight 0.5; given_name (exact; nickname table match; JW ≥ 0.92; else) with a curated, versioned `efp/identity/nicknames.csv`; middle (exact full; initial match; absent; conflict — absent is not evidence against); dob/age (exact dob; age ±1; age ±3; conflict — strong negative); city (exact; same county; same state; conflict) over `usaddress`-normalized strings with a county lookup; case_number (exact; effectively decisive). The settings JSON is versioned under `efp/identity/settings/` and its hash goes into every decision's `decided_by` as `splink:<version>+model:<sha>`.
4. **Parameters from labels, with a published-priors fallback; never EM.** 1,481 rows is too few for stable unsupervised EM. Build a stratified 150-pair labeling queue (rare and common surnames, with and without dob, across sources), present each pair in `efp review identity --label` with the spans and sources, and record my labels as `decisions` of kind `review`. The `labeled_pairs` parameter module fits m and u from the labels plus the published studies once enough labels exist; the `published_priors` module ships a settings JSON built from the literature alone (each value cited) so the stage runs today. Save Splink's `parameter_estimate_comparisons_chart` to `reports/identity/` for whichever module ran, and report which one did.
5. **Decision rule.** Posterior = prior odds × 2^(match weight), converted to probability. ≥ `identity.confirm_threshold` (0.99): confirmed automatically, waterfall stored; between `identity.review_threshold` (0.90) and 0.99: `needs_review`; below 0.90: unresolved, and the chain stops (the news gate reads this). A candidate that agrees only on name, state and year has zero evidence and a posterior equal to the prior, which for a common name is far below 0.90; write the test that proves this property holds for the ten most common surnames in the dataset. Thresholds are pre-registered in `config.toml`; a sensitivity re-run at 0.995 is a flag (`--confirm-threshold 0.995`) that writes to a separate decision batch tagged `sensitivity`, never overwriting the main run.
6. **Outputs.** One `decisions` row per row (kind `identity`, outcome `confirmed` / `needs_review` / `unresolved`, `evidence_ids` the supporting captures) and the accepted candidate's waterfall in `identity_candidates.waterfall_json`. `efp identity explain <row_id>` prints the prior with its components, each comparison's level and Bayes factor, the posterior, and the verbatim spans behind each agreeing field. `efp review identity` walks the review band showing the same, and records my decision with rationale as a new `decisions` row (kind `review`), never editing the model's.
7. **The F3 audit set.** After the full run: 50 confirmed rows, oversampling common surnames and rows that were in the review band, laid out in `reports/identity/f3_audit.md` so I can re-derive each by hand from the captures. After my verdicts (recorded as decisions of kind `review` with outcome `audit_correct` / `audit_wrong`), compute the false-confirmation rate with a bootstrap interval, separately for common-name and rare-name strata, and put it in the report. If it is not near zero, propose the threshold change and stop.

## Tests

- Prior computation against hand-computed values; the floor rule; the ±5 cohort widening; cohort-free fallback.
- Each comparison's levels on synthetic pairs; the nickname table; absent middle name not negative; dob conflict strongly negative.
- The guarantee: name+state+year-only candidates for common surnames never reach 0.90.
- Threshold routing to the three outcomes; sensitivity batch does not overwrite.
- `explain` output contains every component the spec's audit requires.
