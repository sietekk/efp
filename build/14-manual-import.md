## What to build

1. **`efp import --row <id> --source newsbank|newspapers_com|westlaw|portal <file> [--url U] [--retrieved-at T] [--note N]`.** The command hashes the file, copies it into the store under its hash, writes one `captures` row with `manual_source` set, `tool = 'manual'`, `tool_version` = the package version, `url_requested` = the URL I give (or the licensed database's record URL), `retrieved_at` = the time I give or the file's modification time (recorded as such in `headers_json`), and `http_status NULL`. Then it extracts text with the documents component (PDFs) or trafilatura (saved HTML), stores the text capture, writes an `articles` row with `source_kind = 'manual'` (news sources) or a `court_records` row (`portal`), and advances the row's `news` stage (or `court` for `portal`) exactly as the automated path would. The spec's `manual_source` CHECK allows `newsbank`, `newspapers_com`, `westlaw`; add `portal` by migration and say so in the report.
2. **Hunchly and browser captures.** Accept a Hunchly case export (its JSON or CSV plus the saved pages) and ingest each page as above with the URL, timestamp and page hash Hunchly recorded; also accept a plain "Save as PDF" from the licensed interface with the URL typed in. Record which form arrived in `headers_json.import_kind`.
3. **Batch form.** `efp import --batch <csv>` with columns `row_id, source, file, url, retrieved_at, note`, so an afternoon in the library produces one CSV and one command; per-line failures do not stop the batch and are listed at the end.
4. **Queue bookkeeping.** An import for a row that is in `queues/newsbank.csv` (or `licensed_other.csv`, `assisted_dockets.csv`) marks that queue line done in a `queue_status` table; `efp status --queues` shows outstanding versus done per queue. The queues themselves are regenerated by their builds; the status table persists.
5. **Import kinds as modules.** `import.pdf`, `import.saved_html`, `import.hunchly` under `[stages.import]`, policy `first_available` by file kind, so a new capture format is one module.
6. **Provenance parity.** The result must be indistinguishable in structure from an automated capture: hash, body in the store, text capture, article or record row, stage advance, audit-log entry. The report (build 19) can then state what fraction of evidence came from each route (`captures.manual_source` and `articles.source_kind`).
7. **Safety.** The command refuses a file outside `paths.data_dir`'s import inbox unless `--allow-anywhere` is passed (so a stray path cannot pull an unrelated document in), refuses to import for a row whose identity is `unresolved` (the same gate as the news stage), and never fetches anything from the network.
